# Anomaly Detection on Synthetic Sales Data

Isolation Forest model that flags unusual daily sales patterns — demand
spikes, one-day dips, and multi-day flatlines — across multiple SKUs.

> **Portfolio demo.** All data is synthetic and generated by
> `data/generate_data.py`. Nothing here comes from an employer or any
> proprietary system.

## How it works

1. `data/generate_data.py` builds 180 days of daily sales for 4 SKUs
   (weekly seasonality, trend, noise) and injects 31 labeled anomalies of
   three known types: `spike`, `dip`, `flatline`. Seeded RNG, reproducible.
2. `src/detect.py` computes per-SKU features (sales level, rolling mean/std,
   deviation from rolling median, day-over-day change, day of week) and fits
   an Isolation Forest (`contamination=0.045`) per SKU. Exposes
   `flag_anomalies(df) -> df` with a boolean `flagged` column.
3. `src/evaluate.py` scores the flags against the injected labels and saves
   per-SKU plots to `reports/`.

## Run it

```bash
pip install -r requirements.txt
python data/generate_data.py
PYTHONPATH=src python src/evaluate.py
```

## Sample results (real run, 720 rows / 31 injected anomalies)

```
precision      : 0.528
recall         : 0.613
F1             : 0.567
```

Honest caveats: unsupervised detection on 31 anomalies is a hard task, and a
fixed contamination rate means false positives are expected. The flatline
runs are caught most reliably; small dips are the hardest. This is reported
as-is — no tuning was done against the test labels beyond choosing sensible
rolling-window features.

## Layout

```
data/generate_data.py   # synthetic data + anomaly injection (seeded)
data/sales.csv          # generated sample data (regenerable)
src/detect.py           # IsolationForest flagging logic
src/evaluate.py         # precision/recall/F1 vs injected labels + plots
reports/                # per-SKU anomaly plots (generated, gitignored)
```
